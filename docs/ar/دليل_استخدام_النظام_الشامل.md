## 1. نظرة عامة
منصة ERP عربية متكاملة: مبيعات، مشتريات، مخزون، محاسبة، CRM، موارد بشرية، صيانة، أسطول، POS، تقارير، صلاحيات متقدمة، وسجلات تدقيق.

الأدوار النموذجية: مدير النظام، محاسب، مسؤول مخزون، مندوب مبيعات، مسؤول مشتريات، أمين صندوق POS، مشرف صيانة، مسؤول أسطول، مسؤول موارد بشرية، مدقق.

## 2. تسجيل الدخول والإعداد الأولي
- الدخول: الصفحة الرئيسية أو `/admin/`.
- المستخدم الافتراضي (إن وُجد): `superadmin / admin123` (يجب تغييره فوراً).
- خطوات أولية:
  1. ضبط العملة والخيارات العامة (AppSettings).
  2. إنشاء المستخدمين والمجموعات وإسناد الأذونات.
  3. إدخال الحسابات المحاسبية الأساسية أو استيرادها.
  4. إدخال المنتجات والمواقع.

## 3. الهيكل العام والتنقل
- قائمة جانبية / علوية للأقسام.
- كل قائمة تدعم: بحث، فلاتر، ترتيب، أحياناً تصدير CSV/XLSX.
- ألوان/أيقونات للحالات (مثل: مدفوعة / مسودة / مغلقة).

## 4. إدارة الشركاء (Partners)
- إنشاء شريك باختيار النوع: عميل / مورد / كلاهما.
- يُنشأ تلقائياً Customer أو Supplier مرتبط.
- للمورد: حقول محاسبية (حد ائتماني، رصيد افتتاحي، شروط سداد). تُستخدم لاحقاً في التقارير وكشف المورد.
- تجنب تكرار الأسماء؛ استخدم الهاتف للتفريق عند الحاجة.

## 5. إدارة علاقات العملاء (CRM)
- قائمة العملاء (تصنيف: عميل رئيسي / عادي).
- تتبع فرص / اتجاهات (قبول، عمولات) حسب ما هو مفعل.
- مؤشرات أساسية عبر تقارير الاتجاه.

## 6. المبيعات (Sales)
خطوات إنشاء فاتورة:
1. اختيار العميل.
2. إضافة البنود (منتج، كمية، سعر، خصم إن وُجد).
3. حفظ وإصدار.
4. تسجيل دفعة (جزئية / كاملة) عبر InvoicePayment.
5. متابعة حالة الفاتورة (مدفوعة / متبقية).

كشف حساب عميل: من صفحة العميل أو التقارير (دعم ترقيم الصفحات والتصدير حسب الإعدادات).

قيود مهمة:
- منع تعديل الدفعات المقفلة.
- حماية من التكرار في أرقام إيصالات الدفع.

## 7. نقطة البيع (POS)
التدفق:
1. فتح جلسة (رصيد افتتاحي).
2. إنشاء طلب POS وإضافة البنود.
3. تحصيل الدفعة (finalize_payment) → خصم المخزون + إنشاء فاتورة مبيعات.
4. إغلاق الجلسة (رصيد إغلاق).

ملاحظات:
- عميل نقدي يُنشأ تلقائياً مرة واحدة.
- لا تعدل الطلب بعد أن يصبح مدفوعاً.

## 8. المشتريات (Purchases)
سير العمل النموذجي:
1. أمر شراء (اختياري) → استلام مخزون.
2. إنشاء فاتورة شراء (PurchaseBill).
3. الترحيل: تسجيل قيد (دائن: المورد / مدين: المخزون أو المصروف).
4. مستقبلاً: إضافة مدفوعات موردين لتصفية الأرصدة.

## 9. المخزون (Inventory)
- منتجات مع باركود ووحدة قياس.
- مواقع مخزون (افتراضي/نشط).
- حركات: استلام (زيادة) – صرف/إصدار (نقص) – نقل (إن أضيف لاحقاً) – جرد.
- تقارير: تقادم المخزون، تقييم المخزون.
- تأكد من توفر الكمية قبل البيع / POS.

## 10. المحاسبة (Accounting)
مكونات:
- شجرة الحسابات.
- قيود اليومية.
- إعدادات (حسابات AR/AP وغيرها).

تقارير أساسية:
- قائمة الدخل، الميزانية العمومية، التدفق النقدي.
- تقارير إضافية: دوران المخزون، المقارنات الزمنية.

دفاتر العملاء/الموردين:
- كشف عميل (مكتمل).
- كشف مورد (نسخة أولية: تحسين بإضافة المدفوعات لاحقاً).

## 11. التقارير والتحليلات (Reports & API)
نقاط:
- واجهة API للتقارير: overview, profit-loss, balance-sheet, cash-flow, purchases, sales, inventory.
- تصدير CSV/XLSX + ضغط Gzip لبعض المسارات.
- فلاتر تاريخ + مقارنة فترات.
- استخدم نطاقات صغيرة لتحسين الأداء.

## 12. الموارد البشرية (HR)
- أقسام، شكاوى، تفتيش، مؤشرات أداء (حسب الموديلات المتوفرة).
- تتبع الحالات والتواريخ لتحليلات لاحقة.

## 13. إدارة الأسطول (Fleet)
- المركبات + متابعة صلاحية الوثائق.
- المصاريف تولد قيود محاسبية.
- رحلات وعدادات – مخالفات – تسويات للسائق.

## 14. الصيانة (Maintenance)
- تذاكر / طلبات صيانة (حالات: جديد، قيد التنفيذ، منجز).
- تنبيهات وإعدادات الحد (الحوادث / السلامة) عبر AppSettings.

## 15. المستخدمون والصلاحيات (Users & Permissions)
- مستخدمون + مجموعات + صلاحيات مفصلة (ModulePermission / ResourcePermission).
- مبدأ أقل صلاحية (Least Privilege).
- راجع الأذونات دورياً، خاصة الحسابات المعطلة.

## 16. السجلات والتدقيق (Audit Logs)
- تسجيل عمليات CRUD مع الفرق في الحقول.
- فلاتر (مستخدم، إجراء، تاريخ).
- تصدير للطباعة أو الأرشفة.
- استخدم لإثبات الامتثال ومراجعة الأمان.

## 17. الأمن وحماية البيانات
- تغيير كلمات المرور الافتراضية.
- تفعيل HTTPS عبر عكس (Reverse Proxy).
- تحديث الحزم عند الضرورة مع الاختبار.
- مراقبة التحذيرات (RuntimeWarnings) في التيرمنال.
- تقييد الوصول إلى /admin/ حسب الشبكة (خيار متقدم).

## 18. الأداء وأفضل الممارسات
- تقليل نطاق التاريخ في التقارير الثقيلة.
- الاستفادة من الفهارس الموجودة (created_at / status).
- تجنب الاستعلام داخل حلقات في سكربتات الاستيراد الضخمة.
- caching محتمل لاحقاً (Redis) لتقارير متكررة.

## 19. النسخ الاحتياطي والاسترجاع
- نسخ قاعدة البيانات (sqlite أو PostgreSQL) + مجلد media/.
- أوامر (مثل: backup_now) إن وُجدت.
- جدولة (Windows Task Scheduler أو cron).
- اختبر الاسترجاع دورياً.

## 20. بيئة التشغيل (محلي / Docker)
- تشغيل محلي عبر سكربتات: `start_local.bat`.
- Docker: عبر `docker-compose.yml` (قاعدة بيانات + خدمات لاحقة).
- متغيرات البيئة: إعدادات السرية، مفاتيح، DEBUG.

## 21. الواجهة البرمجية (API)
- توثيق: `/api/docs/`.
- مصادقة: JWT (simplejwt) أو جلسات.
- فلاتر: django_filters (استعمل باراميترات الاستعلام).
- حد زمني: قسم التقارير – استعمل limit لتسريع.

## 22. سير عمل سريع (Quick Workflow)
1. إعداد العملة والحسابات.
2. إضافة مستخدمين وصلاحيات.
3. إدخال المنتجات والمواقع.
4. إضافة العملاء والموردين.
5. (اختياري) تسجيل مشتريات أولية – رفع المخزون.
6. إنشاء فاتورة مبيعات أو طلب POS – تحصيل دفعة.
7. مراجعة التقارير المالية والمخزون.
8. تصدير السجلات للأرشفة.

## 23. استكشاف الأخطاء الشائعة
| المشكلة | السبب المحتمل | الحل السريع |
|---------|---------------|-------------|
| اتصال مرفوض 127.0.0.1 | الخادم متوقف | تشغيل runserver والتأكد من المنفذ 8000 |
| خطأ ترجمة Lazy | تخزين كائن ترجمة كسول في قاعدة البيانات | استخدام gettext الفوري أو تحويل `str()` |
| فشل مهاجرات | تعديل نموذج بدون makemigrations | تنفيذ makemigrations ثم migrate |
| تقرير بطيء | نطاق تاريخ واسع | تضييق النطاق / استعمال limit |
| فشل تدفق POS | مخزون غير كاف | التحقق من الكمية في الموقع الصحيح |

## 24. أفضل الممارسات العامة
- نمط ترقيم موحّد: `INV-YYYYMM-####`, `POS-YYYYMM-####`.
- إغلاق جلسات POS يومياً.
- مراجعة أرصدة العملاء/الموردين شهرياً.
- توثيق التعديلات اليدوية المحاسبية.
- استخدام بيئة اختبار قبل التحديثات الكبرى.

## 25. الأسئلة المتكررة (FAQ)
**س: لماذا تقرير التدفق النقدي فارغ؟**
ج: لا توجد قيود مناسبة في الفترة أو البيانات ما زالت غير مرحّلة.

**س: لا أستطيع تعديل دفعة؟**
ج: ربما مقفلة (locked) – أنشئ دفعة جديدة أو مسار عكسي لاحقاً.

**س: يتكرر إنشاء "عميل نقدي"؟**
ج: النظام يستعمل get_or_create بالاسم نفسه – اترك الاسم الافتراضي.

## 26. أفكار تطوير مستقبلية
- دفعات موردين وربط مباشر بفواتير الشراء.
- لوحة مؤشرات KPI.
- تكامل إشعارات (Email / WhatsApp / SMS).
- دعم تصنيع (BOM / أوامر إنتاج) موسعة.
- طبقة Cache/Analytics متقدمة.
