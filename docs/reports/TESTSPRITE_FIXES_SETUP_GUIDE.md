# دليل إصلاحات TestSprite - خطوات التطبيق

## نظرة عامة
هذا الدليل يشرح كيفية تطبيق الإصلاحات التي تم تنفيذها بناءً على تقرير TestSprite.

---

## الخطوة 1: تطبيق Migrations

### 1.1 تشغيل Migrations
```bash
cd /var/www/tony_erp
python3 manage.py migrate sales
```

**المتوقع:**
```
Running migrations:
  Applying sales.0030_add_accounting_integration... OK
```

### 1.2 التحقق من Migrations
```bash
python3 manage.py showmigrations sales
```

يجب أن ترى `[X]` بجانب `0030_add_accounting_integration`

## الخطوة 2: إعداد البيئة

### 2.1 تحديث ملف .env
أضف السطر التالي إلى `/var/www/tony_erp/.env`:

```bash
# Inventory Settings
ALLOW_NEGATIVE_INVENTORY=0  # 0 = منع المخزون السالب، 1 = السماح به
```

### 2.2 إعادة تشغيل السيرفر
```bash
# إذا كنت تستخدم systemd
sudo systemctl restart gunicorn

# أو إذا كنت في development
python3 manage.py runserver
```

### 3.1 التحقق من الحسابات المطلوبة

1. **حساب العملاء (Accounts Receivable)**

   - كود مقترح: 1210

2. **حساب إيرادات المبيعات (Sales Revenue)**
   - نوع: إيرادات

3. **حساب ضريبة القيمة المضافة المستحقة (VAT Payable)**

من واجهة الإدارة:
1. اذهب إلى **الإعدادات** → **إعدادات المحاسبة**
2. اختر الحسابات التالية:
   - **حساب العملاء (AR Account):** 1210 - العملاء
   - **حساب إيرادات المبيعات:** 4100 - إيرادات المبيعات
   - **حساب ضريبة القيمة المضافة:** 2310 - ضريبة القيمة المضافة
3. احفظ الإعدادات

## الخطوة 4: اختبار الإصلاحات

### 4.1 اختبار API Authentication

```bash
# اختبار Basic Authentication
curl -u username:password http://localhost:8000/api/resource/

# اختبار Health Endpoint
curl http://localhost:8000/api/health/
```

**النتيجة المتوقعة:**
```json
{
  "status": "ok",
  "message": "API is working"
}
```

### 4.2 اختبار CRM Workflow

1. **إنشاء فرصة تجارية (Opportunity)**
   - اذهب إلى CRM → الفرص التجارية → إضافة جديد
   - أدخل البيانات: العميل، القيمة المقدرة، التاريخ المتوقع
   - احفظ

2. **إنشاء عرض سعر من الفرصة**
   - من صفحة تفاصيل الفرصة، اضغط "إنشاء عرض سعر"
   - تحقق من نسخ البيانات تلقائياً:
     - العميل ✓
     - جهة الاتصال ✓
     - القيمة ✓
     - الوصف ✓

3. **قبول عرض السعر**
   - من صفحة تفاصيل عرض السعر
   - اضغط "قبول"
   - تحقق من تغيير الحالة إلى "مقبول"

4. **تحويل إلى فاتورة**
   - من صفحة عرض السعر المقبول
   - اضغط "تحويل إلى فاتورة"
   - **تحقق:**
     - ✓ تم إنشاء فاتورة جديدة
     - ✓ نسخ جميع الأصناف
     - ✓ تحديث حالة عرض السعر إلى "محول"
     - ✓ تحديث حالة الفرصة إلى "ربح"

### 4.3 اختبار الترحيل المحاسبي

1. **إنشاء فاتورة بيع**
   - اذهب إلى المبيعات → الفواتير → جديد
   - أضف أصناف
   - احفظ الفاتورة

2. **ترحيل الفاتورة محاسبياً**
   - من صفحة تفاصيل الفاتورة
   - اضغط "ترحيل محاسبياً"
   - **تحقق:**
     - ✓ ظهور رسالة نجاح
     - ✓ تغيير حالة "مرحّل محاسبياً" إلى نعم

3. **مراجعة القيد المحاسبي**
   - اذهب إلى المحاسبة → القيود اليومية
   - ابحث عن آخر قيد
   - **تحقق:**
     - ✓ مدين: حساب العملاء = إجمالي الفاتورة
     - ✓ دائن: إيرادات المبيعات = المجموع الفرعي - الخصم
     - ✓ دائن: ضريبة القيمة المضافة = قيمة الضريبة

### 4.4 اختبار Pagination

1. اذهب إلى **المبيعات** → **الفواتير**
2. إذا كان لديك أكثر من 50 فاتورة:
   - ✓ يجب رؤية أرقام الصفحات في الأسفل
   - ✓ اختبر التنقل بين الصفحات
3. اختبر تغيير عدد العناصر:
   - اختر 25 / 50 / 100 / 200
   - ✓ يجب تحديث القائمة

### 4.5 اختبار المخزون السالب

**إعداد الاختبار:**
```bash
# في .env
ALLOW_NEGATIVE_INVENTORY=0  # منع المخزون السالب
```

1. **إنشاء منتج بكمية محدودة**
   - اذهب إلى المخزون → المنتجات
   - أضف منتج جديد مع كمية = 10

2. **محاولة بيع كمية أكبر**
   - أنشئ فاتورة جديدة
   - حاول إضافة 15 من المنتج
   - **النتيجة المتوقعة:** 
     - ✗ رسالة خطأ: "الكمية المتوفرة في المخزن غير كافية"
     - ✗ لا يتم إضافة الصنف

3. **السماح بالمخزون السالب (اختياري)**
   ```bash
   # في .env
   ALLOW_NEGATIVE_INVENTORY=1
   ```
   - أعد تشغيل السيرفر
   - كرر المحاولة
   - **النتيجة المتوقعة:** ✓ يتم قبول الكمية

## الخطوة 5: Production Workflow Testing

### 5.1 اختبار بدء أمر إنتاج

1. **إنشاء BOM (Bill of Materials)**
   - اذهب إلى الإنتاج → BOM → إضافة
   - أضف منتج نهائي + مواد خام

2. **إنشاء أمر إنتاج**
   - اذهب إلى الإنتاج → أوامر الإنتاج → جديد
   - اختر BOM
   - احفظ

3. **بدء الإنتاج**
   - من صفحة تفاصيل الأمر
   - اضغط "بدء الإنتاج"
   - **تحقق:**
     - ✓ تم إنشاء Material Issue
     - ✓ تم خصم المواد الخام من المخزن
     - ✓ تحديث الحالة إلى "قيد التنفيذ"
     - ✓ تسجيل تاريخ البداية

## الخطوة 6: مراقبة الأخطاء

### 6.1 فحص Logs

```bash
# فحص آخر 50 سطر من logs
tail -n 50 /var/www/tony_erp/logs/django.log

# مراقبة logs بشكل مباشر
tail -f /var/www/tony_erp/logs/django.log
```

### 6.2 الأخطاء الشائعة وحلولها

#### خطأ: "لم يتم ضبط حساب العملاء"
**الحل:**
- اذهب إلى الإعدادات → إعدادات المحاسبة
- اختر حساب العملاء (AR Account)
- احفظ

#### خطأ: "لا توجد مواقع مخزنية"
**الحل:**
- اذهب إلى المخزون → المواقع
- أضف موقع افتراضي (مثل: "المستودع الرئيسي")

#### خطأ: Migration فشل
**الحل:**
```bash
# إعادة المحاولة
python3 manage.py migrate sales --fake-initial

# إذا استمرت المشكلة
python3 manage.py migrate sales 0029  # Rollback
python3 manage.py migrate sales       # Re-apply
```
